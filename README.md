# AUTO-SKGC：学科与通用知识图谱自动构建 Agent

这是一个从本科毕设延展而来的知识图谱自动构建项目集，分为两个可独立阅读的阶段：面向课程资料的学科知识图谱流水线，以及后来在 Coze Coding 环境中实现的通用领域多 Agent 系统。

## 项目结构

| 目录 | 内容 | 入口 |
| --- | --- | --- |
| [`subject-kg/`](subject-kg/README.md) | 论文阶段的九模块教育知识图谱系统：OCR、预处理、抽取、匹配、定义、规范化、新类型探索、图谱构建、质量评估 | `subject-kg/run.py` |
| [`general-kg/`](general-kg/README.md) | Planner-Worker-Critic 三层 LangGraph Agent，包含领域模式规划、设计确认、来源路由、十个 Worker 和质量回滚 | `general-kg/src/main.py` |
| [`general-kg/docs/architecture.md`](general-kg/docs/architecture.md) | 通用版架构、节点职责和数据流 | - |

原始论文、答辩 PPT、课程讲义、模型缓存、运行日志、抽取数据库及内部业务案例原文没有放入本目录。两个阶段的示例输入均为公开常识或重新编写的演示内容。

## 系统演进

学科版针对课程 PDF/PPT：按固定流程解析材料，抽取实体和关系，去重、补充定义、规范类型、构建图谱并评估覆盖率、连通性和语义质量。教育场景增加了知识点重要性、关系强度和章节溯源等信息。

项目按阶段交付：先完成九模块学科构建基线，再把工作流拆成十个可单独验收的 Worker 能力并扩展为 Planner-Worker-Critic 架构，最后进行跨领域端到端验证。

通用版把领域差异从固定 Worker 逻辑中抽离。Planner 根据“领域 + 下游用途”生成候选本体、属性、词表、来源策略和 Worker 提示；设计确认层在需求不足时先返回澄清问题；Worker 按计划执行；Critic 评估并决定放行或回滚。新增领域主要通过任务描述和动态生成的领域配置适配。

## 项目记录与案例

后续三门学科的抽样迭代记录中，知识点抽取准确率从 50% 以上提升到 90% 以上。对应的抽样清单、标注口径和逐轮数据没有随本仓库公开，因此该数值可用于理解项目记录，不能仅凭当前仓库独立复算。它也不等同于论文中人工标注对照实验的 Precision/Recall，或通用版 Critic 的图谱质量分。

通用版案例记录如下。原始业务输入和完整图谱未公开，分数是对应运行的历史结果，不代表其他数据集上的保证值。

## 使用边界

- LLM 输出是候选知识，不是事实来源。用于教学、运营或决策前，应由领域人员核验关键实体、关系和来源证据。
- 准确率、质量分和图结构会随输入材料、模型版本、提示词、检索结果和阈值变化；历史分数不构成质量承诺。
- OCR 对扫描质量、排版、公式和图表敏感。公开版本没有附带原课程资料，复现实验需要自备并获准使用的输入文件和评测集。
- 通用版联网检索依赖运行环境提供的搜索服务，时效、来源许可和返回内容可能变化。
- 不要向未获批准的模型或服务提交个人信息、学生信息、客户数据、企业内部文档或其他受限内容。按数据所有者要求先脱敏并确认授权。
- 调用模型、搜索、对象存储和 Coze 服务可能产生费用；本仓库不包含任何凭据，也不代替服务商的访问控制。
- 仓库未声明代码开源许可证。教材、课件、模型、依赖和第三方材料仍受各自许可约束；需要复用代码时请先与作者确认授权。
